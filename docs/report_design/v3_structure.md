# レポート v3 — 構造設計

> **対象**: Zynect 広告監査レポート v3.0
> **作成日**: 2026-05-01
> **目的**: 顧客が15秒でハイライトを把握し、3分で優先アクションを意思決定できるレポートのページ別構造を確定する。
> **読者**: テンプレート実装担当 / プロダクトオーナー / 営業

---

## 全体方針

### v3 の3つの設計原則

1. **15秒ルール**: 表紙＋エグゼクティブサマリ（P1+P2）だけで顧客が「全体の健康状態」「最大インパクトの打ち手」「想定改善額」を把握できる。
2. **3軸表示の徹底**: 数値スコア・指標は **必ず「現状値・業界平均・Zynect推奨値」の3軸** で並べる。単独数値は出さない。
3. **10原則の可視化**: 検出された問題と推奨アクションは **必ず米満氏理論の原則ID**（P1〜P9 / M-α〜M-λ）に紐付け、Zynect の独自視点を見える化する。

### 全体ページ構成

| ページ | セクション | 想定読了時間 | 主要メッセージ |
|--------|-----------|------------|--------------|
| P1 | 表紙 | 5秒 | 誰宛・何の文書・いつの分か |
| P2 | エグゼクティブサマリ | 15秒 | 全体スコア + 想定インパクト + 3行要約 |
| P3 | 優先アクションプラン Top5 | 60秒 | 次に何をやるか |
| P4 | 媒体別詳細診断 — Google | 30秒 | Google 媒体の問題と評価 |
| P5 | 媒体別詳細診断 — Meta | 30秒 | Meta 媒体の問題と評価 |
| P6 | 媒体別詳細診断 — TikTok | 30秒 | TikTok 媒体の問題と評価 |
| P7 | Zynect Insights（独自視点） | 60秒 | 他社監査では見えない指摘 |
| P8 | 付録 — 用語集・原則解説 | （随時参照） | 専門用語の解説と10原則 |

合計：約4分で全文読了、ハイライト把握は1分以内。

## ページ2: エグゼクティブサマリ

### 目的
15秒で「全体の健康状態」「最大インパクトの打ち手」「想定改善額」を把握できる。

### 必須要素

#### ブロック1: 3行要約（顧客が15秒で読める量）
- 1行目: 現状診断（例: 「広告アカウント全体の健康スコアは 50/100 点。業界平均 65 点を15点下回ります」）
- 2行目: 最大の問題（例: 「TikTok 一部キャンペーンが赤字運用中で、月額 ¥72,000 の損失が発生しています」）
- 3行目: 改善見込み（例: 「優先アクション Top5 を実行することで、月額 ¥185,000 の削減見込みです」）

#### ブロック2: Health Score 比較（3軸ビジュアル）
横棒3本のチャート:
```
業界平均        ████████████░░░░  65点
Zynect 推奨水準 ████████████████  80点
現状           ██████░░░░░░░░░░  50点  ← 改善余地 30点
```

#### ブロック3: 推定改善インパクト（KPIカード）
| 指標 | 現状 | 改善後（見込み） | 差分 |
|------|------|----------------|------|
| 月次広告費 | ¥750,000 | ¥630,000 | ▼¥120,000 |
| 月次CV | 124件 | 165件 | ▲41件 |
| 平均CPA | ¥6,048 | ¥3,818 | ▼¥2,230 |
| 月次ROAS | 2.1 | 3.0 | ▲0.9 |

> 注: 「改善後（見込み）」は優先アクション Top5 を全件実行した場合の試算。信頼度ラベル（高/中/低）を併記。

#### ブロック4: スコア内訳（媒体別ミニチャート）
3媒体それぞれの Health Score を1行ずつ並べ、業界平均との差分を可視化。

### 設計上の注意
- ブロック1の3行は **Claude API による生成**（顧客語化が必要なため）
- ブロック3の数値は **計算ロジックによる試算**（再現性を確保）
- 「改善後（見込み）」が下振れリスクとして信頼度ラベル必須

## ページ3: 優先アクションプラン Top5（最重要ページ）

### 目的
顧客が「次に何をすべきか」を判断し、社内会議で意思決定できる。

### 1アクションあたりの構造

各アクションは以下6項目で構成（必須）:

```
┌────────────────────────────────────────────────────┐
│ ① アクション名（顧客語）                              │
│    例: TikTok の赤字キャンペーンを一時停止し、       │
│       LP（広告クリック後の遷移先ページ）を改善する  │
│                                                    │
│ ② なぜ重要か（10原則との接続）                        │
│    例: 【P3: 結果指標非依存原則】広告費が売上を      │
│       上回る状態を放置すると、AI自動入札の学習が     │
│       「失敗データ」を覚えてしまい長期的に悪化する。  │
│                                                    │
│ ③ 実行手順                                           │
│    1. [運用代行] 該当キャンペーン（TikTok_Broad）     │
│       の予算を50%縮小（即時、5分）                   │
│    2. [運用代行+貴社] LP の主訴求コピーを A/B 検証    │
│       （3営業日、UI担当との連携必要）                │
│    3. [運用代行] ターゲティングを類似1%→3%に         │
│       広げ、母集団を拡大（30分、即時）              │
│                                                    │
│ ④ 想定効果                                           │
│    月額 ¥45,000 〜 ¥85,000 の損失削減                │
│    ROAS: 0.90 → 1.5（推奨水準2.0には届かないが      │
│    赤字脱出）                                         │
│    信頼度: 中（LP改善の効果は実装次第）              │
│                                                    │
│ ⑤ 所要時間と難易度                                   │
│    所要時間: 合計 約 4 営業日                        │
│    難易度: 中（LP改修に貴社UI担当の関与が必要）       │
│                                                    │
│ ⑥ 関連ルールID                                       │
│    C03 / T05 / M-γ                                   │
└────────────────────────────────────────────────────┘
```

### Top5 の選び方（ロジック）

優先順位は以下の式で算出:
```
priority_score = severity_weight × estimated_impact_yen × confidence_weight
                 ÷ effort_hours
```

- `severity_weight`: critical=5, high=3, medium=1.5, low=0.5
- `estimated_impact_yen`: 計算ロジック（v3_content_strategy.md 参照）
- `confidence_weight`: 高=1.0, 中=0.7, 低=0.4
- `effort_hours`: 所要時間（小さいほど優先度上昇）

これにより「クイックウィン（小工数で大インパクト）」が上位に来るスコアリングになる。

### 設計上の注意
- 1ページに収めるため、5件のアクションは1件あたり高さ200px程度に制約
- ⑥ 関連ルールID は付録（P8）の用語集に紐付くアンカーとして機能

## ページ4-6: 媒体別詳細診断（各媒体1ページ）

各媒体（Google / Meta / TikTok）に対して以下を1ページずつ展開。

### 構造

#### ブロック1: スコアカード（3軸比較）
```
Google Ads
─────────────────
業界平均        65 ████████████░░░░
Zynect 推奨水準 80 ████████████████
現状           39 ███████░░░░░░░░░  D評価
─────────────────
キャンペーン数: 4 / 月次コスト: ¥448,000 / CV: 63 / ROAS: 2.2
```

#### ブロック2: 10原則別の評価マップ
原則ごとに ○ / △ / × で表示。Google なら9原則、Meta なら10原則。

| 原則 | 評価 | コメント |
|------|------|----------|
| P1 計測精度 | ○ | GA4連携・拡張CV実装済み |
| P2 機械学習保護 | △ | PMax_Main で学習データ不足の懸念 |
| P3 結果指標非依存 | ○ | 該当する停止判断なし |
| P4 ネガティブシグナル | × | 除外KW運用が確認できず |
| P5 Budget Lost 解消 | △ | IS Lost 分析が運用に反映されていない |
| P6 集約優先・分離 | △ | Brand と Generic の分離は OK、SKAG なし |
| P7 バリエーション幅 | × | RSAアセット数が下限 |
| P8 自動化前提判断 | ○ | Smart Bidding 採用済み |
| P9 説明責任 | △ | 判断ログ未整備 |

#### ブロック3: 検出された問題 TOP3（顧客語）
- 1位: PMax_Main で広告が同じユーザーに繰り返し表示されすぎ（フリークエンシー 4.5回／月、推奨上限 4.0）
  - **原因**: 配信対象ユーザー数の枯渇／配信面の偏り
  - **打ち手の方向**: 新しい広告クリエイティブの追加、または対象ユーザー層の拡張

- 2位: 検索広告のクリック率が低い（CTR 2.22%、業界基準 3.0%）
  - **原因**: 広告コピーの訴求弱さ、または検索意図とのズレ
  - **打ち手の方向**: RSA見出しを15本（最大）まで増やす（P7原則）

- 3位: PMax_Main の予算が学習に必要な水準に達していない
  - **原因**: 月予算が顧客獲得単価の20倍未満（学習データ不足）
  - **打ち手の方向**: 予算を月¥150,000以上に引き上げ、または小規模キャンペーンと統合

### 設計上の注意
- 「検出された問題 TOP3」のみ表示し、それ以下は **「他N件、付録参照」** とする（情報過多回避）
- 各問題に「P3: 学習データ破壊防止」のような原則タグを必ず付ける

## ページ7: Zynect Insights（独自視点）

### 目的
**「他社監査ツールでは見えない指摘」を3〜5件強調**し、Zynect の差別化価値を伝える。

### 構造

#### イントロ（30字程度）
> 一般的な監査ツールが指摘しない、米満氏理論ベースの独自視点をお伝えします。

#### Insight 1: 米満氏理論との乖離分析
最も乖離している原則 Top3 を選び、なぜそれが問題かを解説。

例:
> **【P3 結果指標非依存原則】からの乖離 — 最重要指摘**
>
> 一般的な監査では「品質スコアが低いキーワードを停止せよ」と提案されますが、米満氏理論では品質スコアは Ad Rank 算出には使われない**結果指標**であり、停止判断の根拠にすべきではありません。
>
> 貴社アカウントには品質スコア 3 以下のキーワードが12件ありますが、Zynect では **「停止せず、原因変数（推定CTR・広告関連性・LPエクスペリエンス）に分解して打ち手を決める」** ことを推奨します。
>
> **想定インパクト**: 機械的停止を避けることで、CV経路として有効な検索クエリを失うリスクを回避できます。

#### Insight 2: 機械学習保護の観点（P2）
学習フェーズに関する独自視点。

例:
> **【P2 機械学習保護】学習中のキャンペーンに編集を加えてはならない**
>
> Meta_Retargeting は学習フェーズ突入から3日目です。このタイミングで予算・ターゲット・最適化イベントを変更すると学習がリセットされ、最適化が永久に進まないリスクがあります。
>
> 一般的な監査ツールはこのタイミング判定を行いませんが、Zynect は学習フェーズ中の編集を **「文脈依存で要承認」** として判断ログに残します。

#### Insight 3: ネガティブシグナル保持の観点（P4）
削除された運用要素の保持価値について。

#### Insight 4-5: 媒体特有の独自指摘
EMQ、iOS14対応、PMax アセットグループ別分析など、媒体特性に応じた独自指摘。

### 設計上の注意
- このセクションが **Zynect の差別化を最も強く伝えるページ**。営業資料として読まれる頻度が高い
- 各 Insight には「**他社監査ではこう言われがち** → **Zynect ではこう判断する**」の対比構造を必ず入れる

## v3 構造設計の引き継ぎ事項

1. **テンプレート分割**: v2 の `templates/report.html`（単一ファイル）から v3 では `templates/v3/cover.html` / `summary.html` / `actions.html` / `platform.html` / `insights.html` / `appendix.html` の6分割推奨。
2. **3軸データ供給**: ページ4-6 のスコアカードは「業界平均」「Zynect 推奨値」「現状値」の3つを必ず供給する必要がある。業界平均値の出典管理は `v3_content_strategy.md` 参照。
3. **優先アクション Top5 のロジック実装**: 上記 priority_score 式を `analyzers/priority_ranker.py`（新設）に実装する。
4. **Zynect Insights ページのコンテンツ生成**: 完全に Claude API 依存（定性推論層）。プロンプトテンプレートを別途設計。
5. **印刷時のページ分割**: Playwright PDF 生成時に CSS の `page-break-before: always;` で各セクションを必ず改ページする。
