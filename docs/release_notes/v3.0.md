## ハイライト

v3 は **「監査ツールの出力ログ」から「営業資料として顧客に渡せる戦略レポート」への進化** が主目的です。Day 1 の問題分析（v2 の課題 5 観点）を基に設計し、Day 4-5 で実装しました。

| 観点 | v2 (旧) | **v3 (新)** |
|------|--------|-------------|
| ページ構成 | 1〜3 ページ（情報密度過剰） | **8 ページ**（表紙 / サマリ / 優先アクション / 媒体別×3 / Insights / 付録） |
| 専門用語 | 注釈なし羅列 | **初出時に括弧書きで顧客語併記**（60 語の翻訳辞書） |
| 想定効果 | 数値なし | **月次削減見込み額 + 信頼度 + 効果発現週数** を必ず併記 |
| 比較軸 | 単独数値 | **業界平均 / Zynect 推奨 / 現状の3軸比較**（円形チャート + 横棒チャート） |
| 差別化 | 米満氏理論への言及なし | **Zynect Insights セクション + 各アクションに 9+10 原則タグ併記** |
| 重大問題 | severity ベタ並び | **「⚠️ 今すぐ対処すべき重大問題」を別枠で固定表示**（Top5 と独立） |

## 新機能

### 1. v3 レポート構造（8 ページ構成）
- **表紙**: 企業名（御中）+ 担当者名（様）+ 業界カテゴリ + 機密表記
- **エグゼクティブサマリ**: 3 行要約 + Health Score 3軸 + 推定改善インパクト KPI
- **優先アクションプラン Top5**: パターン C（effort 重視・クイックウィン優先）でランキング
- **⚠️ Critical Alerts**: severity=critical を最大 3 件、Top5 と独立した別枠で固定表示
- **媒体別詳細診断 ×3**: Google / Meta / TikTok を各 1 ページ。データ無し媒体はプレースホルダ表示
- **Zynect Insights**: 米満氏理論ベースの独自視点（「他社監査ではこう言われがち」 vs 「Zynect ではこう判断する」対比）
- **付録**: 用語集 25 語 + 9+10 原則の要約

### 2. 業界別ベンチマーク比較
- `config/benchmarks.yaml` に 5 業界 × 3 媒体 × 5-6 メトリクス（合計 80 セル中 62 セル入力済み）
- 出典: AdEspresso / Databox / WordStream / Varos / Powered by Search の 2024-2025 年ベンチマーク（62 出典）
- 「業界平均 / Zynect 推奨水準 / 現状」の 3 軸を **円形チャート + 横棒チャート** で可視化

### 3. 想定効果の数値試算（3層ハイブリッド）
| 層 | 責務 | 実装 |
|----|------|------|
| 層1 | ルール定義の固定値 | `rules/*.yaml` の `expected_impact` フィールド（90 ルールに付与済み） |
| 層2 | 計算ロジック | `engine/impact_estimator.py` — キャンペーン別または現状値ベースで月次削減額を試算 |
| 層3 | 定性推論 | `engine/claude_insights.py` — Claude API による顧客語翻訳・ナラティブ・Zynect Insights 生成 |

層3 は ANTHROPIC_API_KEY 未設定時または月額予算 ¥30,000 超過時、**自動でテンプレート代替フォールバック** に切替（人間レビュー前提運用）。

### 4. Pattern C 優先順位スコアリング
`engine/priority_ranker.py` — クイックウィン優先（小工数 × 大インパクトを上位化）:
```
priority_score = (severity × impact × confidence) / sqrt(effort_hours) × quick_win_bonus
```
重み調整は `config/priority_weights.yaml` で外出し済み。Day 4 ユーザー確定で **パターン C を採用**、別パターン（A: severity 重視 / B: confidence 重視）も `docs/report_design/v3_priority_score_weights.md` に保管。

### 5. 並行運用モード
`pipeline.py` に `--report-version` 引数を追加:
```bash
python pipeline.py run yamamoto_demo                          # v2 のみ（既存後方互換）
python pipeline.py run yamamoto_demo --report-version v3      # v3 のみ
python pipeline.py run yamamoto_demo --report-version both    # v2 + v3 を同時生成（並行運用期間用）
```

### 6. クライアント設定 v3 スキーマ
`config/clients.yaml` に **`company` / `contact` / `report` ブロック** を追加。
v3.0 では旧 `name` フィールドを後方互換として保持（v3.2 で廃止予定）。

## 既知の制約

### A. Anthropic API 未設定時のフォールバック
- ANTHROPIC_API_KEY 未設定の場合、層3 (Claude API) は呼び出されず、テンプレート代替文で生成される
- 影響: 顧客語翻訳・ナラティブ・Zynect Insights が機械的な文章になる
- 対応: API キー設定 + 月額 ¥30,000 予算内で本格運用を推奨

### B. mobile_app 業界が未対応
- `config/benchmarks.yaml` は 5 業界（ec_retail / saas_b2b / finance / education / local_service）のみ対応
- bandal_gaming（ゲーム/モバイルアプリ）等は暫定で `ec_retail` にマップ
- 対応: 2026-Q3 で `mobile_app` 業界をベンチマーク追加予定

### C. PDF サイズ
- v2: 0.85 MB / v3: **約 1.9 MB**（Day 5 で 2.74 MB → 1.9 MB に軽量化、目標 1.5 MB は未達）
- Web フォント @import を削除しシステムフォント採用済み。これ以上の軽量化はフォントサブセット化が必要

### D. 媒体別ページのデータ依存性
- 取得データに含まれない媒体は「本媒体は分析対象外（データ未取得）」プレースホルダ表示
- yamamoto_demo の現状は Meta のみデータあり、Google/TikTok はプレースホルダ

### E. CPA / ROAS の「—」表示
- conversions=0 のキャンペーンは CPA 算出不能のため `avg_cpa: None` → 「—」表示
- これは仕様（0 円表示は誤誘導するため）

### F. TikTok 業界平均の未収集セル
- 残 18 セル（特に finance / local_service の TikTok 系）は要調査のまま
- TikTok Business 公式 APAC Q1 2025 Insight Report が publicly accessible でないため

## 移行手順（並行運用 → v3 切替）

### Phase 1: 並行運用（1 週間）
```bash
python pipeline.py run all --report-version both
```
両方の PDF が生成される。Slack / CRM / メール通知は v2 に紐付いたまま。

### Phase 2: v3 切替（リリース日）
```bash
python pipeline.py run all --report-version v3
```
- 顧客への配布は v3 PDF（`{client_id}_report_v3.pdf`）
- Slack 通知用は v2 が必要なら `--report-version both` のまま継続

### Phase 3: v2 廃止（v3.2 想定）
- `outputs/pdf_report.py` および `templates/report.html` を deprecation
- `--report-version` のデフォルトを v3 に変更（現在は v2）
- legacy `name` フィールドの読み込みを廃止し、`company.name` 必須化
