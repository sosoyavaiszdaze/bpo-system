## 2. メインメッセージ (1 段落)

```
弊社が他代理店と異なる本質的な差は、「運用の自動化レイヤー」です。
24h 365 日稼働する自動診断エンジンが、企業ごとの状況に合わせて
適切な提案を自動生成し、ChatWork へ自動投稿します。
人間 (運用担当) は例外対応と大型判断のみに集中。
これにより、1 担当者が 30 クライアントを並列運用可能になります。
```

## 3. Zynect 差別化要素 3 点 (P8 追加セクション案)

### 訴求 1: 24h 365 日の自動診断・自動提案

```markdown
■ 自動運用エンジン (4 段構成)

[1. 自動診断]   毎朝 09:00、5 媒体 277 ルールの監査が走る
                Pixel 健全性 / CAPI 状態 / EMQ スコア等を全件チェック

[2. 自動評価]   検知された問題を 6 グループ (計測基盤 / 配信学習 等) に分類
                3 層インパクト (確実値 / 現実値 / 上限値) で効果額を試算

[3. 自動提案]   企業の状態に応じて 8 種類の依頼を自動生成
                ECフォース 権限 / CAPI 設定 / 1st party データ受領 等

[4. 自動投稿]   ChatWork ルームへ Zynect Auto-Reporter 名義で自動投稿
                顧客側はチャット 1 つで全ステータス把握可能
```

### 訴求 2: 横展開性 (10 分でフル運用開始)

```markdown
■ 新規クライアント運用開始フロー

競合代理店:                    Zynect Media:
  1. ヒアリング 1 週間            1. ChatWork ルーム作成 (3 分)
  2. 初回監査 1 週間              2. setup スクリプト実行 (5 分)
  3. 初回提案 1 週間              3. 初回自動診断 + 自動提案投稿 (2 分)
                                 ─────────────────────
合計 3 週間                       合計 10 分

→ kickoff day から自動診断が稼働、月内に全提案を投げ切ります。
```

### 訴求 3: 人間担当者のスケーラビリティ

```markdown
■ 1 担当者あたりの管理クライアント数

競合代理店:        5-10 client (営業の手作業限界)
Zynect Media:    30 client    (自動運用エンジンによる 3-6 倍効率化)

人間担当者は以下のみに集中:
  ・想定外の数値変動への対応
  ・大型予算判断 (月 100 万円超の戦略変更)
  ・クライアント直接相談 (ChatWork 自動では拾えない要望)
```

## 3-bis. 525 ルール体制 (ADR-013 で実現)

### 二段構えの監査体系

```
[広告数値診断]   既存 277 ルール (Layer A)
                  ├ Google Ads 108 / Meta 70 / TikTok 46
                  ├ SEO 45 / AdTruth 15 / Common 15
                  └ KPI 数値 (CTR/CPA/ROAS) 異常検知

[環境/法令診断]  新規 248 ルール (Layer 0-3、ADR-013)
                  ├ Layer 0 Foundation 68 (法令遵守 / プライバシー / 計測基盤等)
                  ├ Layer 1 Vertical 70 (薬機法/景表法/業法、9 業界)
                  ├ Layer 2 EC Platform 30 (ECフォース 等 6 プラットフォーム)
                  └ Layer 3 Precision Category 80 (計測精度 / オーディエンス / DQ 等)

合計 525 ルール = 「数値診断 277」+「環境診断 248」
```

### 5/7 提案訴求ポイント

#### 1. 日本の業界規制を自動指摘
- **薬機法**: 化粧品 56 効能 / 健食 医薬品的効能 (V-EC-01/02)
- **景表法**: 優良誤認 / 有利誤認 / 打消し表示 / **ステマ規制** (F-LC-01〜05)
- **特商法**: 表記事項 / 定期購入解約導線 (F-LC-04, V-EC-08)
- **個情法 + 電気通信事業法**: 外部送信規律 / CMP 導入 (F-LC-06, F-LC-10, F-PP-02)
- **業法系**: 宅建業法 / 金商法 / 医療広告ガイドライン / 職業安定法 (Vertical 層)

#### 2. Foundation 層で「広告を止められない運用基盤」を保証
- 計測基盤 (Pixel/CAPI/EMQ/サーバーサイド GTM) の前提条件診断
- アカウント停止リスク事前検知 (F-AH-01)
- 同意管理 (CMP) 未導入の早期警告
- 法令系は **disclaimer 必須** (Zynect は法務専門家ではなく、指摘レベル)

#### 3. 環境マッチング (applies_to) で精度高い指摘
- pilotton (vertical=ec_d2c, ec_platform=ecforce) では:
  - ✅ V-EC-* 12 件 + P-EF-* 8 件が適用
  - ❌ V-SS-* / P-SH-* 等は除外 (環境不一致)
- 30 client 増加時も自動最適化、誤指摘ゼロ



| 項目 | 競合代理店一般 | **Zynect Media** |
|------|------------|------------|
| 監査頻度 | 月 1 回 (担当者手動) | **毎朝 09:00 自動** |
| 監査ルール数 | 10-30 項目 (担当者選択) | **525 ルール (5 媒体 + 5 層自動診断)** |
| **日本法令対応** | 営業の経験頼り (もれあり) | **薬機法/景表法/特商法/業法を自動指摘 (Layer 0-1)** |
| **Foundation 層** | なし | **CMP/CAPI/ssGTM 等 68 ルールで運用基盤保証** |
| **5 層自動診断** | 単一の数値診断のみ | **数値 + 法令 + 業界 + プラットフォーム + 精度の 5 層** |
| 提案生成 | 営業の経験 (ばらつきあり) | **8 ルール × 状態評価で自動** |
| 提案文面の品質 | 担当者の文章力依存 | **統一テンプレート (Jinja2 集中管理)** |
| 完了確認 | 営業からの催促 (2-3 回) | **3 日連続クリーン自動検知** |
| 月次レポート | Excel で手作成 (4-8 時間/件) | **PDF 自動生成 + ChatWork 自動添付 (5 分/件)** |
| 効果額試算 | 楽観値のみ (営業に有利) | **3 層 (確実値 / 現実値 / 上限値) で過大評価回避** |
| 新規開始 | 2-3 週間 | **10 分** |
| 担当者 1 名の対応上限 | 5-10 client | **30 client** |
| 横展開の容易さ | 都度カスタマイズ必要 | **clients.yaml + スクリプト 1 発** |
| クライアント返信の管理 | メール散在 | **ChatWork ルーム集約 (永続検索可能)** |

## §4. TO-12 軸「不正ブロック実行 vs CV 保全」(2026-05-05 新設)

既存 11 軸に **TO-12** を追加 (`config/rules/tradeoff_axes.yaml`):

```
左極 (block_aggressive)             右極 (cv_preservation)
不正完全遮断・広告費節約最大       CV 保全最優先・ブロックは記録のみ
                  中央 (investigate)
                  一定期間モニタリング後判断
```

媒体別ブロック手段:

| 媒体 | 主要手段 | IP 除外 |
|------|---------|--------|
| Meta | Custom Audience exclusion + Audience Network 除外 | ❌ 非対応 |
| Google | IP 除外 (最大 500) + キーワード/プレースメント除外 | ✅ |
| TikTok | Custom Audience + プレースメント除外 | ❌ 非対応 |
| LP 共通 | AdTruth タグ → cloaking page (媒体非依存) | (LP 側) |

**「不正は止めるが CV は守る」を数値で約束**: ブロック前後 14 日の CV 推移を `engine/cv_preservation_monitor.py` で自動計測、損失 15% 超で閾値自動緩和提案。月次レポートに **CV 保全率** を必須掲載。

## §5. 二層判断フレーム (ADR-009 Accepted)

### 第一層: 運用憲章 (Operating Charter) — kickoff day で初期合意

```yaml
operating_charter:
  primary_kpi: cv_max | cpa_min | roas_max | balanced
  cv_loss_tolerance_pct: 5 | 10 | 15 | 20
  delegation_scope: black_only | grey_threshold | full_review
  charter_version: "1.0"
```

### 第二層: 都度確認 + Zynect 推奨

灰ゾーン (不正シグナル高 × CV 発生中) 検知時:
- `engine/recommendation_engine.py` が運用憲章 + 過去類似判断 5 件から推奨生成
- ChatWork で 5 択提示 (推奨採用 / 別案 / モニタリング / 詳細要求 / 憲章見直し)

### 一貫性担保 3 仕組み

1. **判断ログ全件記録** (`outputs/client_preferences/{client}_decisions.yaml`)
2. **月次整合性レポート** (charter 整合率 + 過去判断整合率を ChatWork に併記)
3. **四半期憲章レビュー** (`_quarterly_charter_review.md.j2` で運用方針見直し)

### 競合比較

| 観点 | 競合代理店 | **Zynect Media** |
|------|----------|----------------|
| 顧客方針の扱い | 「丸投げ」or「一律設定」 | **運用憲章で構造化、四半期更新** |
| 灰ゾーン判断 | 営業主観 (ばらつき) | **Zynect 推奨 + 顧客 5 択 + 履歴ログ** |
| 一貫性 | 時系列で破綻 | **整合率を月次計測、ズレ時に能動提案** |

## 7. 提案 Q&A 想定 (営業対応用)

### Q1: 「自動投稿だと不正確な提案が来るのでは?」

**A**: 弊社の提案エンジンは 2 段階の安全機構を備えています。
1. **trigger 条件 + 前提条件チェック**: 状態が確実に「依頼可能」になってから初めて発火
2. **cooldown 7-30 日**: 同じ依頼を短期間で連発しない
3. **日次 cap 1 件**: 1 日 1 ルームへの提案投稿は最大 1 件
4. **dry-run モード**: 投稿前に弊社運用担当 (山本) が確認可能

### Q2: 「人間担当者は何をするのか?」

**A**: 運用担当は以下に集中します。
- 想定外の数値変動 (CPA 急騰、新規キャンペーン投入時等) への即時対応
- 大型予算判断 (月 100 万円超の戦略変更)
- ChatWork 自動投稿への顧客返信を Claude API 補助で読解、状態更新
- 月 1 回の振り返り MTG (zoom) での総括

### Q3: 「他社にも同じ自動化が広まるのでは?」

**A**: 弊社の競合優位は以下の点です。
- 5 媒体 277 ルール = **米満氏理論ベースの独自監査ロジック** (他社は 10-30 項目)
- **3 層インパクト + 6 グループ重複排除** = 過大評価しない誠実な数値提示
- **ECフォース 等の EC プラットフォーム特化テンプレート** = 顧客の運用に即した依頼
- 上記は弊社の運用ノウハウを ADR-001〜012 として体系化済、模倣には 6 ヶ月以上を要します
