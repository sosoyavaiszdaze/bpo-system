# レポート v3 — 専門用語 → 顧客語 翻訳辞書

> **対象**: Zynect 広告監査レポート v3.0 で使用する全用語の翻訳定義
> **作成日**: 2026-05-01
> **目的**: 顧客（広告運用未経験の経営者・マーケ責任者）が読んで理解できる表現に統一する
> **読者**: テンプレート実装担当 / Claude API プロンプト設計者 / レポート QA 担当
> **収録語数**: 60語（指標 18 / 媒体機能 22 / 運用概念 13 / 計測 7）

## 利用ルール

### ルール1: 初出時の括弧書き併記
本文で初めて専門用語を使う場合は、平易な説明を括弧書きで併記する。

例:
- × 悪い: 「フリークエンシーが上限超過しています」
- ○ 良い: 「フリークエンシー（同一ユーザーへの広告表示回数）が上限超過しています」

### ルール2: 2回目以降は省略可
同一ページ内で2回目以降は専門用語のみで OK。ページが変わったら再度括弧書き。

### ルール3: 顧客向けには日本語、業界人向けには併記
- 顧客向けレポート本文: 日本語表現を主、専門用語を括弧
- Zynect Insights: 専門用語を主、日本語を括弧（業界知識を持つ方も読むため）

### ルール4: 数値は単位を明記
- × 「ROAS 2.0」 → ○ 「ROAS 2.0倍（広告費1円あたり売上2.0円）」
- × 「CTR 3%」 → ○ 「CTR 3.0%（クリック率：広告表示100回あたり3回クリック）」

## カテゴリ1: 基本指標（18語）

### 1. CPA (Cost Per Acquisition)
- **平易な説明**: 顧客獲得単価。広告経由で1人の顧客（または1件のCV）を獲得するのにかかった広告費
- **初出時併記例**: 「CPA（顧客獲得単価）が ¥6,048 です」
- **リスク説明**: CPA が高いと広告効率が悪く、利益を圧迫します

### 2. CPC (Cost Per Click)
- **平易な説明**: 1クリック単価。広告がクリックされるたびにかかる費用
- **初出時併記例**: 「平均CPC（1クリック単価）¥150」
- **リスク説明**: CPC が業界平均より高い場合、広告ランクの低下や競合増加が原因の可能性

### 3. CPM (Cost Per Mille)
- **平易な説明**: 広告表示1,000回あたりの費用
- **初出時併記例**: 「CPM（広告表示1,000回あたりの費用）¥800」
- **リスク説明**: CPM 上昇は競合増加・需要過多のサイン

### 4. CTR (Click Through Rate)
- **平易な説明**: クリック率。広告が表示された回数のうち、何%がクリックされたか
- **初出時併記例**: 「CTR（クリック率）3.0% — 広告表示100回あたり3回クリック」
- **リスク説明**: CTR が業界平均（検索 3.0%、SNS 1.0%）を下回ると、広告コピーや訴求の見直しが必要

### 5. CVR (Conversion Rate)
- **平易な説明**: コンバージョン率。クリックしたユーザーのうち、何%が購入・問合せ等に至ったか
- **初出時併記例**: 「CVR（コンバージョン率）2.5%」
- **リスク説明**: CVR が低い場合、ランディングページや訴求のミスマッチが原因の可能性

### 6. CV (Conversion)
- **平易な説明**: コンバージョン。広告経由で発生した購入・申込・問合せなど成果1件
- **初出時併記例**: 「月次CV（コンバージョン）数 124件」
- **リスク説明**: CV 数の急減は計測タグ不具合や配信停止の兆候

### 7. ROAS (Return On Ad Spend)
- **平易な説明**: 広告費用対効果。広告費1円あたりの売上
- **初出時併記例**: 「ROAS 2.0倍（広告費1円あたり売上2.0円）」
- **リスク説明**: ROAS 1.0 を下回ると赤字運用。Zynect 推奨水準は 2.0 以上

### 8. ROI (Return On Investment)
- **平易な説明**: 投資収益率。広告費を含む全コストに対する利益率
- **初出時併記例**: 「ROI（投資収益率）」
- **リスク説明**: ROAS は売上ベース、ROI は利益ベース。混同に注意

### 9. インプレッション (Impression)
- **平易な説明**: 広告が表示された回数
- **初出時併記例**: 「インプレッション（表示回数）50万回」
- **リスク説明**: インプレッション急減は予算枯渇・入札不足のサイン

### 10. リーチ (Reach)
- **平易な説明**: ユニーク到達ユーザー数。同じユーザーに何度表示されても1人とカウント
- **初出時併記例**: 「リーチ（到達したユニークユーザー数）12万人」
- **リスク説明**: リーチが頭打ちになっている場合、配信対象が枯渇している可能性

### 11. フリークエンシー (Frequency)
- **平易な説明**: 同一ユーザーへの広告表示回数（月あたり）
- **初出時併記例**: 「フリークエンシー（同一ユーザーへの広告表示回数）4.5回／月」
- **リスク説明**: 月4.0回を超えると広告疲れ（Ad Fatigue）が発生し CTR が低下

### 12. IS (Impression Share)
- **平易な説明**: インプレッションシェア。獲得可能だった表示機会のうち、自社広告が獲得した割合
- **初出時併記例**: 「IS（インプレッションシェア：表示獲得率）70%」
- **リスク説明**: IS が低い = 表示機会を競合に取られている。Budget Lost か Rank Lost の分解が必要

### 13. IS Lost (Budget) / IS Lost (Rank)
- **平易な説明**: 表示機会を逃した原因の分解。Budget = 予算不足、Rank = 広告品質または入札不足
- **初出時併記例**: 「IS Lost (Budget)（予算不足による機会損失率）30%」
- **リスク説明**: Budget Lost を先に解消するのが Zynect 推奨（P5 原則）

### 14. CPL (Cost Per Lead)
- **平易な説明**: リード獲得単価。問合せや資料請求1件にかかった広告費
- **初出時併記例**: 「CPL（リード獲得単価）¥3,000」
- **リスク説明**: CPL は購入前段階のため CPA より安価。LTV と紐付けて評価

### 15. LTV (Lifetime Value)
- **平易な説明**: 顧客生涯価値。1人の顧客から得られる累計売上
- **初出時併記例**: 「LTV（顧客生涯価値）¥80,000」
- **リスク説明**: LTV を見ずに CPA だけで判断すると、長期顧客への投資機会を逃す

### 16. AOV (Average Order Value)
- **平易な説明**: 平均注文額。1注文あたりの売上
- **初出時併記例**: 「AOV（平均注文額）¥12,000」

### 17. CR (Creative)
- **平易な説明**: クリエイティブ。広告画像・動画・コピーなどの素材
- **初出時併記例**: 「CR（広告クリエイティブ）の入替が必要です」

### 18. KPI / KGI
- **平易な説明**: 重要業績評価指標 / 重要目標達成指標。KGI は最終目標、KPI は中間指標
- **初出時併記例**: 「KGI（最終目標）月次売上1,000万円、KPI（中間指標）CPA ¥3,000」

## カテゴリ2: 媒体機能・キャンペーン種別（22語）

### 19. PMax / Performance Max
- **平易な説明**: Google の全配信面（検索・YouTube・GDN・Discover）に AI が自動配信するキャンペーン
- **初出時併記例**: 「PMax（Performance Max：Google AI 全自動配信キャンペーン）」
- **リスク説明**: ブラックボックス領域が大きいため、アセットグループ別分析が重要（P9 原則）

### 20. Smart Bidding
- **平易な説明**: Google の AI 自動入札。tCPA / tROAS 等の目標値を AI が達成するよう入札を自動調整
- **初出時併記例**: 「Smart Bidding（Google AI自動入札）」
- **リスク説明**: 学習中の頻繁な変更は学習をリセットする（P2 原則）

### 21. tCPA / tROAS
- **平易な説明**: 目標CPA / 目標ROAS。Smart Bidding で AI に達成させる目標値
- **初出時併記例**: 「tCPA（目標CPA）¥3,000」

### 22. Search Ads / 検索広告
- **平易な説明**: Google 検索結果に表示されるテキスト広告
- **初出時併記例**: 「検索広告（Google検索結果に表示されるテキスト広告）」

### 23. Shopping Ads / ショッピング広告
- **平易な説明**: 商品画像・価格・店舗名を表示する Google ショッピング広告
- **初出時併記例**: 「ショッピング広告（商品画像つき広告）」

### 24. Display Ads / GDN
- **平易な説明**: Google Display Network。提携サイトに表示されるバナー広告
- **初出時併記例**: 「GDN（Google Display Network：提携サイト向けバナー広告）」

### 25. Demand Gen
- **平易な説明**: Google の Discover/Gmail/YouTube 向けビジュアル重視キャンペーン
- **初出時併記例**: 「Demand Gen（Discover/Gmail/YouTube向け需要喚起キャンペーン）」

### 26. RSA (Responsive Search Ad)
- **平易な説明**: レスポンシブ検索広告。複数の見出しと説明文を入稿し、AI が最適な組み合わせで配信
- **初出時併記例**: 「RSA（レスポンシブ検索広告：複数見出しを AI が組み合わせる広告）」

### 27. Advantage+ / ASC+
- **平易な説明**: Meta の AI 自動最適化機能。配置・オーディエンス・クリエイティブを AI が最適化
- **初出時併記例**: 「Advantage+（Meta AI 自動最適化機能）」
- **リスク説明**: 媒体仕様変化が早く、四半期ごとに最新仕様の確認が必要

### 28. CBO (Campaign Budget Optimization)
- **平易な説明**: キャンペーン単位予算最適化。広告セット単位ではなくキャンペーン全体の予算を AI が配分
- **初出時併記例**: 「CBO（キャンペーン単位予算最適化）」

### 29. ABO (Ad Set Budget Optimization)
- **平易な説明**: 広告セット単位予算最適化。各広告セットに固定予算を割り当て
- **初出時併記例**: 「ABO（広告セット単位予算最適化）」

### 30. Reels / リール
- **平易な説明**: Meta（Instagram/Facebook）の縦型ショート動画フォーマット
- **初出時併記例**: 「Reels（リール：Meta の縦型ショート動画）」

### 31. Carousel / カルーセル
- **平易な説明**: 複数画像をスワイプして閲覧できる広告フォーマット
- **初出時併記例**: 「カルーセル広告（複数画像をスワイプ閲覧する広告）」

### 32. Spark Ads
- **平易な説明**: TikTok でオーガニック投稿を広告として配信する形式
- **初出時併記例**: 「Spark Ads（TikTok オーガニック投稿の広告化）」

### 33. Smart+
- **平易な説明**: TikTok の AI 自動最適化機能（Advantage+ の TikTok 版）
- **初出時併記例**: 「Smart+（TikTok AI 自動最適化）」

### 34. Audience Network
- **平易な説明**: Meta の外部アプリ・サイト配信網
- **初出時併記例**: 「Audience Network（Meta の外部配信網）」
- **リスク説明**: 誤クリック・自動再生課金が発生しやすく、除外管理が重要

### 35. UGC (User Generated Content)
- **平易な説明**: ユーザー生成コンテンツ。一般ユーザーが作成した動画・画像
- **初出時併記例**: 「UGC（ユーザー生成コンテンツ：一般の方が作った動画素材）」

### 36. オーディエンス / Audience
- **平易な説明**: 配信対象ユーザー層
- **初出時併記例**: 「オーディエンス（配信対象ユーザー層）」

### 37. 類似オーディエンス / Lookalike (LLA)
- **平易な説明**: 既存顧客と似た特性を持つ新規ユーザー層
- **初出時併記例**: 「類似1%（Lookalike 1%：既存顧客に最も似た上位1%のユーザー層）」

### 38. リターゲティング / Retargeting
- **平易な説明**: 過去にサイト訪問・商品閲覧したユーザーに再度広告を配信
- **初出時併記例**: 「リターゲティング（再訪促進広告）」

### 39. プロスペクティング / Prospecting
- **平易な説明**: 新規ユーザーへの初回アプローチ広告
- **初出時併記例**: 「プロスペクティング（新規顧客向け広告）」

### 40. 入札戦略
- **平易な説明**: AI または手動でクリック単価・コンバージョン単価を調整するルール
- **初出時併記例**: 「入札戦略（広告費の支払いルール）」

## カテゴリ3: 運用概念（13語）

### 41. 学習フェーズ (Learning Phase)
- **平易な説明**: AI が配信を最適化中の状態。Meta は週50CV、TikTok も同様の基準
- **初出時併記例**: 「学習フェーズ（AI が配信最適化を進めている状態）」
- **リスク説明**: 学習中に予算・ターゲット・最適化イベントを変更すると学習がリセットされる

### 42. 学習データ不足
- **平易な説明**: 月予算が顧客獲得単価の20倍未満で、AI が最適化に必要なデータを収集できない状態
- **初出時併記例**: 「学習データ不足（AI が学習する材料が足りない状態）」
- **リスク説明**: 予算増額または小規模キャンペーンの統合が必要

### 43. 広告疲れ / Ad Fatigue
- **平易な説明**: 同じ広告を見続けたユーザーがクリックしなくなる現象。フリークエンシー上昇のサイン
- **初出時併記例**: 「広告疲れ（Ad Fatigue：同じ広告を見続けたユーザーがクリックしなくなる現象）」

### 44. クイックウィン / Quick Win
- **平易な説明**: 小工数で大きな改善が見込める施策
- **初出時併記例**: 「クイックウィン（少ない労力で効果が出る施策）」

### 45. 3x Kill Rule
- **平易な説明**: 「目標CPAの3倍を超えた広告は停止」という従来の手動運用ルール
- **初出時併記例**: 「3x Kill Rule（CPAが目標の3倍を超えた広告を停止する従来ルール）」
- **リスク説明**: Zynect では自動入札時代には適用しない（P3 / P8 原則）

### 46. SKAG (Single Keyword Ad Group)
- **平易な説明**: 1キーワード=1広告グループの細分化構造。旧来のベストプラクティス
- **初出時併記例**: 「SKAG（1キーワード=1広告グループ構造）」
- **リスク説明**: Zynect では否定。集約推奨（P6 原則）

### 47. ネガティブシグナル
- **平易な説明**: 「配信を止めるべき要素」をAIに教える情報（除外キーワード・除外オーディエンス等）
- **初出時併記例**: 「ネガティブシグナル（配信を止める対象を AI に教える情報）」
- **リスク説明**: 削除でなく除外保持で AI 学習が強化される（P4 原則）

### 48. ポジティブシグナル
- **平易な説明**: 「成果が出た要素」を AI が学習するための情報（CV・購入完了等）

### 49. オークション / Auction
- **平易な説明**: 広告枠の入札競争。各広告主が同時に入札し、最も高評価の広告が表示される
- **初出時併記例**: 「オークション（広告枠の入札競争）」

### 50. Ad Rank（広告ランク）
- **平易な説明**: Google の広告掲載順位を決める総合スコア
- **初出時併記例**: 「Ad Rank（広告ランク：掲載順位を決める総合スコア）」

### 51. 品質スコア / Quality Score
- **平易な説明**: Google の広告品質評価（1〜10）。**結果指標**であり停止判断には使わない（Zynect 方針）
- **初出時併記例**: 「品質スコア（Google の広告品質評価：1〜10）」
- **リスク説明**: Zynect では停止判断の根拠にしない（P3 原則）

### 52. オークションインサイト
- **平易な説明**: 競合との比較データ。同じオークションでの相対的な勝率を表示

### 53. オーディエンスシグナル
- **平易な説明**: PMax / Advantage+ で「こういう人に届けたい」と AI に伝えるヒント情報

## カテゴリ4: 計測・トラッキング（7語）

### 54. CV計測タグ / Conversion Tracking
- **平易な説明**: 購入・問合せ等の成果をブラウザに埋め込んだコードで記録する仕組み
- **リスク説明**: タグ不具合は計測欠損 = AI 学習データ欠損につながる（P1 / M-α 原則）

### 55. CAPI (Conversions API)
- **平易な説明**: ブラウザ計測ではなくサーバーから直接 Meta に成果を送信する仕組み
- **初出時併記例**: 「CAPI（Conversions API：サーバーから直接成果を送信する計測手法）」
- **リスク説明**: iOS14 以降のブラウザ計測欠損を補う必須インフラ（M-θ 原則）

### 56. EMQ (Event Match Quality)
- **平易な説明**: Meta の計測品質スコア（0〜10）。ユーザー特定の精度を表す
- **初出時併記例**: 「EMQ（Event Match Quality：Meta の計測品質スコア）」
- **リスク説明**: Purchase イベントは EMQ 8.0+ が目標

### 57. GA4 / Google Analytics 4
- **平易な説明**: Google の最新アクセス解析ツール
- **初出時併記例**: 「GA4（Google Analytics 4：Google の最新アクセス解析）」

### 58. 拡張コンバージョン / Enhanced Conversions
- **平易な説明**: ハッシュ化したメールアドレス等を Google に送信し、計測精度を高める仕組み
- **初出時併記例**: 「拡張コンバージョン（ハッシュ化メールで計測精度を高める仕組み）」

### 59. データドリブンアトリビューション
- **平易な説明**: Google の機械学習でコンバージョン経路ごとの貢献度を算出する評価方式
- **初出時併記例**: 「データドリブンアトリビューション（AI で貢献度を算出する評価方式）」

### 60. ファーストパーティデータ
- **平易な説明**: 自社が直接収集した顧客データ（メールアドレス・購入履歴等）
- **初出時併記例**: 「ファーストパーティデータ（自社で直接収集した顧客データ）」

## 用語の使い分けマップ（顧客語 vs 業界語）

| 状況 | 推奨表現 |
|------|---------|
| 表紙・エグゼクティブサマリ（最重要・15秒読了） | 完全に顧客語のみ。専門用語は **使わない** |
| 優先アクション Top5（顧客が読み込む） | 顧客語が主、専門用語は括弧書き |
| 媒体別詳細（一部専門知識を持つ運用者も読む） | 業界語と顧客語の併記 |
| Zynect Insights（差別化価値の伝達） | 業界語が主、顧客語が補助。原則ID（P1〜P9）を併記 |

## v3 翻訳辞書の引き継ぎ事項

1. **テンプレート実装時のヘルパー関数化**: Jinja2 フィルタ `{{ "frequency" | term_translate }}` のように呼び出せる仕組みを推奨。
2. **辞書の YAML 化**: 本ドキュメントの内容を `config/terminology.yaml` として構造化し、テンプレート / Claude プロンプトの両方から参照可能にする。
3. **業界別の用語追加**: 業界（SaaS / EC / 不動産 / 医療等）に応じて追加すべき専門用語があれば順次拡張。
4. **Claude API への組込み**: システムプロンプトで「以下の用語は必ず括弧書き併記」と辞書を参照させる構造。
5. **多言語対応の考慮**: 将来的に英語版を出す場合の英訳列の追加余地を確保。
