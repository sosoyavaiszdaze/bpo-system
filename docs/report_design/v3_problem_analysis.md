# レポート v3 — 現行レポート問題分析

> **対象**: `reports/2026-05-01/yamamoto_demo_report.pdf` (v2.0 / 全3ページ)
> **作成日**: 2026-05-01
> **目的**: v3 設計の前提として、現行レポートが顧客提出物として機能していない理由を構造化する。
> **読者**: v3 設計担当 / プロダクトオーナー / 営業責任者

---

## サマリ

現行レポートは「監査ツールの出力ログ」であり「顧客向け提案書」になっていない。検出した問題を並べることはできているが、**顧客が次の打ち手を判断できない**ため営業資料として渡せる品質に達していない。

問題を5つの観点（表現・情報設計・実用性・差別化・ビジネス文書）に分けて整理し、各問題に v3 で対応すべき改善案を併記する。

---

## 観点1: 表現の問題（専門用語の羅列）

顧客（広告運用未経験の経営者・マーケ責任者）が読んで意味を理解できない用語が、注釈なしで全ページに散在している。

| 現行表記 | 出現箇所 | 顧客の理解度 | v3 改善案 |
|---------|---------|-------------|-----------|
| フリークエンシー 4.5 が上限超過 | P1 サマリ / P1 異常検知 | ✗ そもそも意味不明 | 「同じユーザーへの広告表示が平均4.5回／月（推奨上限4.0回）。広告疲れの兆候」 |
| ROAS 0.90 で赤字運用 | P1 サマリ / P2 TikTok 詳細 | △ 数字が悪いことは伝わるが基準値不明 | 「広告費1円あたり売上0.90円（赤字）。健全水準は2.0円以上」 |
| 予算 ¥45,000 がCPA×20未満 | P2 媒体別診断 | ✗ ロジック不明 | 「月予算が顧客獲得単価の20倍（推奨）に届かないため、AIが配信を最適化する学習データが集まらない状態」 |
| Ad Rank Lost / IS Lost / 学習データ不足 | P2 全媒体 | ✗ 完全に専門領域 | 用語集（付録）+ 初出時に括弧書き併記 |
| Smart Bidding / PMax / Advantage+ | サマリ | ✗ 媒体機能名と認識されない | 「Google AI自動入札（Smart Bidding）」のように媒体名+機能の併記 |
| Hook Rate / Hold Rate（潜在的に登場） | 媒体詳細 | ✗ 業界外には通じない | 「冒頭3秒視聴率／15秒視聴率」と日本語併記 |

### 数値の単位・基準値の欠如

- 「Health Score 50/100」だけでは「平均はいくつか」「優良は何点か」が不明
- 「平均CPA ¥6,048」は業界平均との比較がないため自社が良いのか悪いのか判断不能
- 「ROAS 2.7（Meta）」も同様

**v3 改善案**: スコア・指標は **必ず業界平均・Zynect推奨値・現状値の3軸で並べる**。単独数値は出さない。

## 観点2: 情報設計の問題（優先度不明・読み順不在）

### 問題1: 「最初に何を見るか」が分からない

P1 サマリの3行コメント、5つの箇条書き、4つの KPI カード、6つのタグ — 情報量が多すぎて視線の逃げ場がない。15秒で読み取れる情報設計になっていない。

### 問題2: 重要度の格付けが不徹底

- 「TikTok_Broad: ROAS 0.90 で赤字運用」（critical）と「PMax_Main: フリークエンシー 4.5 が上限超過」（warning）が同じビュレットスタイル
- × ✗ ! の3記号で区別しているが、severity 単位での視覚的優先順位（一段大きいフォント／色変更／余白）がない

### 問題3: 「次に何をすべきか」が散在

- P1: 「複数の構造的問題が検出された。早期対応を推奨」（曖昧）
- P2: 「→ 新クリエイティブ追加またはオーディエンス拡張」（粒度不明）
- P3: クイックウィン表（具体的だが優先順位不明）
- アクションが3カ所に分散し、顧客はどれを最優先すべきか判断できない

**v3 改善案**:
- エグゼクティブサマリ（P2）は **3行要約 + 1スコア + 推定インパクト** の最小構成に絞る
- **優先アクションプラン Top 5（P3）を独立ページにし、ここを「読むべき1ページ」として強調**
- 媒体別詳細はその後に置く（深掘り資料の位置づけ）

## 観点3: 実用性の問題（アクション粒度バラバラ・想定効果欠落）

### 現行の「推奨アクション」例とその問題

| 現行アクション | 問題 |
|--------------|-----|
| 「ROAS 4.2 と好調。予算20-30%増加を推奨」 | 誰が・いつ・何円増やすか不明。20% と 30% の差をどう判断するか書かれていない |
| 「即時: 予算縮小 → LP改善 → ターゲティング見直し」 | 3工程あるが各工程の所要時間・実行者・想定効果が不明 |
| 「新クリエイティブ追加またはオーディエンス拡張」 | 2択で終わっており、どちらを先にやるかの指針なし |
| 「CPA改善で ¥76,613 削減可能」 | 削減見込みは出ているが、改善する具体施策が書かれていない |

### 想定効果の数値が欠落

「やるとどれだけ改善するか」が読めない。営業資料としては致命的。

- 月次推定削減額の合計値はどこにも出ていない
- 個別施策の改善見込み（例: 「フリークエンシー対応で CPA 約15%改善見込み」）も記載なし

**v3 改善案**: 優先アクションプラン Top 5 では各アクションに以下を必須項目化:
1. アクション名（顧客語）
2. 実行手順（誰が・いつ・どこで・どう実行するか、3〜5ステップ）
3. **想定効果（数値: 月次削減額または改善%、信頼度ラベル付き）**
4. 所要時間と難易度（例: 30分・易、3時間・中）
5. なぜ重要か（10原則との接続）
6. 関連ルールID

## 観点4: 差別化の問題（10原則との接続なし・Zynect独自性が消えている）

### 現行レポートで Zynect の独自性が伝わらない理由

1. **米満氏理論（Google 9原則 / Meta 10原則）への接続が皆無** — 検出された問題が「なぜ Zynect の哲学では問題なのか」が見えない
2. **「他社監査ツールでも出る指摘」と区別できていない** — フリークエンシー上限超過は他社ツールも検出する。Zynect ならではの視点（例: P3 結果指標非依存原則ベースの「品質スコアで停止判断するな」）が前面に出ていない
3. **業界平均との比較なし** — 「うちのスコア D は他社と比べてどうなのか」が分からない
4. **タイトルが「Daily Performance Report」で機能名どまり** — 「広告アカウント健康診断レポート」のような価値語が必要

### 10原則と現行レポートの接続度（Google）

| 原則 | 現行レポートで接続されているか |
|-----|----------------------------|
| P1 計測精度=学習シグナル精度 | × 計測整備状況の記載なし |
| P2 機械学習保護 | △ 「学習データ不足」とは出るが原則名は示されない |
| P3 結果指標非依存 | × 品質スコアの扱いに関する独自視点が出ていない |
| P4 ネガティブシグナル保持 | × 除外運用への言及なし |
| P5 Budget Lost 先行解消 | × 機会損失先行の思想が見えない |
| P6 集約優先・分離 | × 構造設計の話が出ない |
| P7 バリエーション幅最大化 | △ 「新クリエイティブ追加」とは出るが原則名は示されない |
| P8 自動化前提判断 | × 自動入札時代の判断ロジックが見えない |
| P9 説明責任・判断ログ | × 判断ログのセクションがない |

**接続率: 0/9 が明示、2/9 が暗黙的に登場（P2/P7）。差別化材料がほぼ消えている。**

**v3 改善案**:
- 各優先アクションに「P3: 学習データ破壊防止」のように原則名を必ず明記
- P7「Zynect Insights」セクションを新設し、「他社監査では出ない指摘」を3〜5件強調
- レポートタイトルを「広告アカウント健康診断レポート」または「Zynect 広告監査レポート」に変更

## 観点5: ビジネス文書としての問題

### 現行の宛先表記の問題

- 「Prepared for: 山本デモ 様」 — `clients.yaml` の `name: "山本デモ"` をそのまま使用している
- 企業名が出ていない／敬称（御中／様）が固定
- ご担当者名のフィールドがそもそも config に存在しない

### その他のビジネス文書としての品質課題

| 項目 | 現行 | v3 改善案 |
|------|-----|-----------|
| 表紙 | なし。1ページ目にいきなりサマリが乗る | 表紙ページを独立。企業名（御中）+ 担当者名（様）+ 期間 + 版数 |
| 目次 | なし | 8ページ前後の構成では目次は不要。代わりにヘッダーにセクション番号 |
| 用語集 | なし | 付録ページに用語集と原則解説を集約 |
| 機密表記 | "CONFIDENTIAL / CLIENT COPY" のみ | 表紙下部に「機密保持契約に基づく」明記 |
| 生成ツール表記 | "Generated by Zynect Media Agent v2.0" | v3 では強調不要（フッター小さく） |
| 「Daily Performance Report」 | 機能名 | 「広告アカウント健康診断レポート（v3.0）」など顧客にとって意味のある名称 |
| ROAS 0.90 で赤字運用「中（コスト ¥72,000）」 | 改行で本文が途切れている表示崩れ | レイアウト品質チェック（QA）プロセスを v3 で導入 |

### クライアント設定ファイルへの反映

`config/clients.yaml` に以下フィールドを追加する設計改修が必要（詳細は `v3_client_config_spec.md`）:
- `company_name`: 企業正式名称（例: "株式会社山本"）
- `contact_name`: 担当者氏名（例: "山本太郎"）
- `company_honorific`: 企業敬称（"御中" / "様" / 株式会社の前置き）
- `contact_honorific`: 担当者敬称（"様" / "殿" 等）
- `industry`: 業界（業界平均比較に利用）

## v3 設計への引き継ぎ事項

1. **レポートの目的を再定義する**: v2 は「監査ツールの出力ログ」だった。v3 は「顧客が次の打ち手を15秒で把握できる営業資料」と位置づける。
2. **読まれる順序を設計する**: 表紙 → エグゼクティブサマリ → 優先アクション Top5（ここを最重要） → 媒体別詳細 → Zynect Insights → 付録、の8ページ構成。
3. **数値はすべて3軸表示**: 現状値・業界平均・Zynect推奨値を必ずセットで出す。単独数値は禁止。
4. **アクションは6項目で必ず構成**: 名前・手順・想定効果・所要時間・原則接続・ルールID。
5. **専門用語は初出時に必ず翻訳**: 翻訳辞書（`v3_terminology_dict.md`）に従い、本文では「フリークエンシー（同一ユーザーへの表示回数）」のように併記。
